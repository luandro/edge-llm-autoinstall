# GMKtec K11 — Ryzen 9 8945HS, Radeon 780M, 32 GB RAM

The K11's integrated Radeon 780M shares RAM with the CPU. Use **upstream llama.cpp + Vulkan on Mesa RADV**; ROCm is not the default because gfx1103 installation and driver compatibility remain fragile. No NVIDIA CUDA software applies.

## Install

```bash
bash install.sh                    # automatic K11 safe mode
bash install.sh --mode safe        # Gemma 4 E4B Q4_K_M
bash install.sh --mode best        # Gemma 4 26B-A4B Q4_K_M (requires GTT headroom)
bash install.sh --model qwen36     # Qwen3.6 35B-A3B, advanced
bash install.sh --model inkling    # English-focused coding experiment
bash install.sh --model qwen38     # Qwen3.8 27B dense; typically slow on UMA
bash install.sh --model gptoss20b # alternative tool-use model
bash install.sh --backend cpu --mode safe
```

`--mode auto` deliberately chooses **safe** on K11. The installer never adjusts BIOS, kernel or GTT settings itself.

Reported speeds in the accompanying research are **from related Radeon 780M systems, not measured on this K11**. Multiplying performance by 4800/5600 is a bandwidth-based estimate, not an independent benchmark. Real performance depends on RAM channels, thermals, Mesa/kernel versions, quantization and context.

## Practical defaults

- Linux: recent Mesa **RADV**, not AMDVLK; compile current upstream `llama.cpp` with `GGML_VULKAN=ON`.
- Threads: **8** physical CPU cores (instead of 16 SMT threads).
- KV: `q8_0` for K and V, flash attention enabled.
- Start with **8K context**, `-ub 256`, one concurrent request. Benchmark at 16K only after confirming stability.
- For safe mode, run on default GTT. Large modes are opt-in. If the GTT check rejects full Vulkan offload, use safe mode, a limited `--gpu-layers` value or `--backend cpu`.
- Do not blindly add `--spec-type draft-mtp` to every model. The model needs a compatible MTP head and runtime; benchmarking MTP is a separate optimization.
- Do not use SSD swapping as a substitute for enough shared RAM.

### Check GTT, Vulkan, and memory

```bash
vulkaninfo --summary | grep -Ei 'radv|deviceName|driverName'
cat /sys/class/drm/card*/device/mem_info_gtt_total 2>/dev/null
free -h
sudo dmidecode -t memory | grep -E 'Size:|Configured Memory Speed:'
```

The installer warns or rejects a large full-Vulkan configuration if available GPU-addressable GTT is known to be insufficient. This *does not* measure whether 32 GB of physical RAM and thermal headroom are sufficient at runtime.

### Optional, manual, reversible GTT tuning

The report describes raising the Linux TTM/GTT limit from roughly 16 GiB to **22 GiB** (Gemma 26B) or **24 GiB** (Qwen3.6). Such changes can cause GPU hangs or system instability and may need a reboot. They are **not automated**. Apply only after verifying the exact kernel's supported options, keeping console recovery available, and testing system memory pressure. Refer to [`K11_OFFLINE_AI_RESEARCH.md`](K11_OFFLINE_AI_RESEARCH.md), section *Ajuste Opcional e Reversível de Memória GTT*, for the proposed configuration and rollback. The report's commands are research proposals, not verified on your physical K11.

## Speech recognition, translation and summarization (planned)

The current `install.sh` serves **one LLM**. It does **not** yet install the STT/translation pipeline or implement `/v1/audio/transcriptions` and `/v1/translate`. The second implementation phase should add:

1. **STT pt-BR:** default commercially usable Parakeet TDT v3 multilingual INT8 or faster-whisper INT8 with Silero VAD; optional TAGARELA-derived pt-BR fine-tune only after an explicit non-commercial license acknowledgement and legal review.
2. **Translation EN→PT-BR:** [gow-solucoes/opus-mt-en-pt-ct2](https://huggingface.co/gow-solucoes/opus-mt-en-pt-ct2) in CTranslate2 INT8. The model card specifically documents the `>>pob<<` prefix for **Brazilian Portuguese** (not `>>por<<` for European Portuguese). Validate terminology and punctuation.
3. **Summarization pt-BR:** Gemma 4 E4B for quick summaries, Gemma 4 26B or Qwen3.6 for higher fidelity; use chunking and preserve timestamps, proper names, numeric details and decisions.
4. **On-demand switching:** unload large LLMs before running CPU STT/translation, preserve timestamped JSON between stages, and retain a localhost-only API.
5. **Benchmarks:** pt-BR WER/CER (including normalized numbers), translation quality and names, summary factuality, prompt-processing rate, generation rate, peak RSS/GTT, temperatures and end-to-end latency.
