## Phase 2 — Telegram plugin

One minimal explicitly loaded, pinned extension or a thin RPC bridge if no plugin passes review. Keep clean offline CLI usable without Telegram. Start text-only PT-BR/EN private bot, a single authorized user/chat ID allowlist checked before any model or tool invocation, fail closed for unknown senders and groups, deny bot-to-bot loops. Bot token in protected local secret storage, not prompt, logs, repo, USB or command-line args; never ask for token in chat. Run as dedicated unprivileged user, no sudo, restricted workspace and loopback model service; no generic shell or arbitrary filesystem access by default. Bound tool schemas, sanitize model/tool/Telegram outputs, validate arguments and enforce authorization outside model. Read-only tasks first; explicit human approval for writes, external transfers or destructive actions, never infer approval from arbitrary messages. No exposing raw transcripts or community-sensitive files over Telegram by default.

One session per authorized chat/user, bounded queue, one inference at a time; deduplicate updates, persist processed IDs safely, cancellation/timeout/restart without replaying side effects, cap tokens/rounds and Telegram message lengths; record only sanitized metrics. Add status and model info, clear/new session and cancel. No silent cloud escalation, no auto-install arbitrary skills/plugins. Measure incremental prompt overhead (extension with and without Telegram) and daemon RSS/CPU. After text baseline passes, optional consented voice notes: bounded download, safe decode to local PCM, unload STT before LLM if necessary, delete temporary audio by policy; test pt-BR voice and source fidelity. Telegram transport exposes messages/files to Telegram servers: inform users, local CLI is the privacy-preserving offline option.

## Phase 3 — reproducible tests and promotion gates

- CI: shell/Python/TypeScript lint/typecheck and unit tests, deterministic routes, valid/invalid tool args, no execution of arbitrary model-suggested commands, manifest/profile selection and rollback. Mock model and Bot API tests (no real token) for auth, rejection, dedup, long responses, timeout, cancellation, reconnect, restart, concurrent messages, malformed content, prompt injection and approval.
- Laptop: actual paired base/merged models + harness comparison, cold/warm separated, at least five repeated smoke tasks; no tool, read-only system facts, Portuguese writing/summary/translation, multi-step read and error recovery; record full accuracy rubric, task success per minute, total prompt/cache/decode tokens, calls/turns, time-to-first-token, latency p50/p95, process tree RSS/PSS and host PSI/swap, load/unload times, failures. Use safe isolated fixtures, human review factual answers. Cloud GPU benchmarks only quality/feasibility, not CPU performance.
- Physical Pi5 4/8/16 GB and N95/N97: repeat paired tests; headless 64-bit OS, active cooling, exact kernel/CPU/runtime versions, thermal/throttling, one slot, offline test (network disabled CLI) and separately authorized Telegram live E2E (WAN). Test sequential STT+translation+summary+agent and sustained eight-hour mixed load; no OOM, sustained paging, unbounded loop, unauthorized calls or data egress. Pi 4GB must stay within actual RAM/4K unless separately measured; fail closed if prompt exceeds budget.
- Define task-specific quality thresholds before measuring; require zero unauthorized side effects, no loss of critical intent, no regressions on supported rollback path. Promote only when matched task accuracy and latency/RAM improve or meet declared requirements. Record raw sanitized evidence, limitations and failed/skipped arms; keep safe Qwen and existing Hermes rollback. No production-ready claims before tests pass.
